# Director 的第一個 Vibe Coding 實例

你負責目標、指揮、監督、驗收；Codex 負責寫程式、檢查、整理版本。

## 先看作品

用瀏覽器開啟 `index.html` 即可，不需安裝網頁框架。按「跟我打聲招呼」測試互動。

## 四個工具的分工

| 工具 | 白話用途 | Director 要做什麼 |
| --- | --- | --- |
| Codex | 按你的需求建立、修改與驗證網頁 | 給目標、看成果 |
| Git | 在本機保存有名稱的版本，可比較與復原 | 確認值得保存的里程碑 |
| GitHub | 在線上保存 Git 專案，讓他人審查 | 指定帳號／倉庫與分享範圍 |
| 本教學開發包 | 任務書、操作提示、驗收標準和範例程式 | 重用模板 |

「本教學開發包」是這個專案的教材，不是宣稱官方有名為 Codex Development Package 的產品。該名稱尚待你提供來源確認。若指 OpenAI Developers plugin，官方描述它用於 OpenAI API／Agents 開發；本例是普通靜態網頁，沒有 API 整合。

## 第一輪：下達任務

在 Codex 選擇一個空資料夾，貼上：

```text
我是 Director。請建立一個非常簡單的繁體中文個人介紹網頁。
標題是「我的第一個網頁」，介紹我是 David。
加一個「跟我打聲招呼」按鈕，點擊後顯示問候文字。
風格清爽，手機和電腦都能閱讀。使用 HTML、CSS、JavaScript。
請自行完成檔案、預覽和驗證，把技術選擇交給你。
驗收：按鈕有效、390px 與 1440px 無水平捲動、鍵盤可操作。
先完成本機版本，回報可開啟的成果、驗證證據與未完成事項。
```

你現在已經有這個範例；要從零重做，請另選空資料夾。

## 第二輪：監督

只在需要時貼這一句，不必逐行看程式：

```text
用三點回報：已完成什麼、實際驗證了什麼、哪個問題需要我決定。
每個驗證結果附上證據；不要把尚未執行的檢查說成通過。
```

## 第三輪：提出一次修改

```text
把標題改成「David 的 AI 學習筆記」，按鈕改成「開始學習」。
點擊後顯示「今天，我完成了第一個網頁！」。
請保留其他版面，完成後驗證互動，給我看修改前後差異。
```

這是練習題，範例目前仍保持第一輪內容。你說需求，讓 Codex 修改。

## 第四輪：驗收與保存版本

親自花一分鐘：看標題、點按鈕、縮窄視窗。美感與內容由你判斷，技術驗證要求 Codex 提供。

通過後貼：

```text
本機版本驗收通過。請檢查 Git 狀態，只保存本例檔案，
建立一個描述清楚的 commit，回報版本編號與是否還有未保存變更。
若 Git 身分未設定，詢問我需要的名稱與電子郵件；不要自行虛構。
```

commit 是保存一個版本；push 是把版本送到 GitHub。GitHub 倉庫保存原始碼；要有公開網站網址，還需要網站發布。

## 第五輪：使用 GitHub

本資料夾已初始化 Git，但尚無遠端倉庫。你只需提供自己的 GitHub 倉庫連結。若沒有倉庫，在 GitHub 建立空白 repository：名稱可用 `my-first-webpage`，自行選 Private 或 Public，先不要加入 README／license／gitignore。

然後貼：

```text
我的 GitHub 倉庫是「貼上倉庫連結」。請核對目的地與現有遠端設定，
把驗收通過的本機版本推送到這個倉庫。不要強制推送。
若需登入，告訴我最少的操作；完成後給我 GitHub 連結與提交版本。
```

帳號授權需要你本人完成；不要把密碼或 token 貼在聊天中。
本例尚未推送；尚未取得目的地與登入驗證。

## 你應學會的指揮公式

「做給誰」＋「要達成什麼」＋「範圍」＋「驗收條件」＋「執行自主權」。

少問「你會不會做」，直接下達「請完成並附證據」。把「看起來好了」改成可檢查的條件。
